### Fixed

- On Windows, stopping a terminal reader whose input is a pipe no longer hangs. The reader waited on the input handle for input, but a pipe handle reads as ready whether or not input is queued, so a reader over a pipe went into a read that cancellation could not end, and `Stop`, shutdown and an external-editor handoff waited on it for good (seen as a 30 minute `internal/codingagent` test timeout in Windows CI). A pipe is now polled for queued input, so cancelling a reader returns at once and leaves later input to the next reader. A console, which `pig` itself reads, is waited on as before. <!-- fix: f9648c6fd5 -->
